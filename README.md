# ブロック崩しメーカー

MRS GAMES向けのスマートフォン中心Webゲームです。

昔ながらのブロック崩しを遊び、将来的にはプレイヤー自身がステージを作成・テストプレイ・投稿できるゲームを目指します。

## 現在の実装範囲

Phase 1：基本ゲーム＋プリセット11ステージ

- 通常、2Hit、3Hit、破壊不能、爆発、アイテム、ワープブロック
- パドル拡大、ボール追加、ボール拡大、爆発ボール、1UP
- スマートフォンのスライド操作とPCのマウス操作
- ポーズ、BGM・効果音設定、ローカルベストタイム
- 固定内部座標（360×560）からのレスポンシブ表示

## 操作

- 指またはマウスを左右に動かしてパドルを操作
- ボール待機中に盤面をタップして発射
- マルチボール中は最後のボールを失ったときに残機が減少
- 再発射待機中とポーズ中はタイム停止

## ロードマップ

1. 基本ゲーム＋プリセットステージ
2. ステージメーカー
3. ローカル保存・テストプレイ
4. Cloudflare D1による投稿・ランキング・共有

ステージデータには`schemaVersion`を持たせ、プリセット・ローカル保存・投稿ステージで共通利用できる構造にしています。

## Phase 4A：投稿・個別URL

作者がテストクリアした端末内ステージをCloudflare Pages FunctionsからD1へ投稿し、`/s/<公開ID>`で他のユーザーが直接プレイできます。

- 投稿API：`POST /api/stages`
- 取得API：`GET /api/stages/<公開ID>`
- 個別URL：`GET /s/<公開ID>`
- D1マイグレーション：`migrations/0001-phase-4a.sql`
- Pages Functions対象：`_routes.json`の`/api/*`と`/s/*`のみ

Pagesには次の環境設定が必要です。

- D1バインディング：`STAGES_DB`（本番・プレビューは別DB）
- Secret：`RATE_LIMIT_SALT`（本番・プレビューは別値を推奨）

公開済みデータはAPIから変更しません。端末内の元ステージは投稿後も編集でき、配置を変更すると作者クリア状態が無効になります。再度テストクリアして投稿すると、新しい公開IDが発行されます。

## Phase 4B：投稿一覧とランキング

- 当月の投稿一覧：`GET /api/stages`。日本時間の`YYYY-MM`月キーで20件ずつ表示し、投稿日時＋数値IDのカーソルを利用します。次ページは初回ページの先頭位置を上限にして、新規投稿の割り込みによる重複を抑えます。
- 前月TOP30：前月（日本時間）に投稿された公開ステージのみ、前月のユニークプレイ端末数順。歴代BEST10：公開中の全投稿を通算ユニークプレイ端末数順。同数の場合はユニーククリア端末数、投稿日時、数値IDの順です。
- プレイ：`POST /api/stages/<公開ID>/plays`（初回発射時）。クリア：`POST /api/stages/<公開ID>/clears`（60分有効の署名付きプレイID）。端末×ステージ、端末×ステージ×月の初回だけ計上し、同じクリア報告を再送しても増えません。クリア率はユニーククリア端末数÷ユニークプレイ端末数で、プレイゼロは「—」と表示します。
- D1マイグレーション：`migrations/0002-phase-4b.sql`。投稿本文と公開IDは変更せず、匿名の訪問明細、集計値、短時間のアクセス制限用レコードを追加します。
- `COMMUNITY_SIGNING_KEY` Secretを本番・プレビューそれぞれ別のランダム値で設定します。投稿制限の`RATE_LIMIT_SALT`とは別値です。匿名端末Cookie `__Host-bbm-visitor` はランダムIDとその署名のみで、`HttpOnly; Secure; SameSite=Lax; Path=/; Max-Age=31536000`。IPや作者名は保存しません。D1の訪問キーはIDから生成した署名値で、IPは短時間のアクセス制限用に日付・Secret込みの不可逆ハッシュだけを保存します。
- 集計APIが失敗・制限された場合でもゲーム開始、操作、クリア表示は継続します。ランキング値は端末単位の目安であり、Cookie消去や別端末、改造クライアントに対して厳密な人数・実プレイ証明はできません。

### 明細の保持と将来の削除

Phase 4Bでは自動削除を実装しません。`stage_month_visitors`と`community_rate_limits`は増加するため、D1容量と日次使用量を監視します。将来、集計済みの前月ランキングを保持したまま、少なくとも前月末から60日を経過した月明細と古い分単位の制限行を、少量ずつ定期削除する運用を追加します。`stage_visitors`は通算ユニーク人数の再計上防止に必要なので、ランキングの通算仕様を変えない限り削除しません。削除前にはバックアップと集計整合性の確認が必要です。

## Phase 4C：共有

投稿完了画面と共有ステージのクリア画面から、個別URLを共有できます。

- Web Share API対応環境では端末の共有画面を表示
- 未対応環境では共有URLをクリップボードへコピー
- 共有画面のキャンセルはエラーとして扱わない
- 共有処理が失敗した場合もURLコピーへ切り替える
- 作者名や自由入力文は使用せず、ステージ名と定型文だけを共有
